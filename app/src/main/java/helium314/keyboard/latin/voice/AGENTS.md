# latin/voice

Microsoft MAI-Transcribe-2-Streaming dictation directly through Azure Speech SDK 1.52.0.

## Direct files
- `MaiTranscriptionClient.kt` - main-looper lifecycle, supported device/region validation, advisory boundaries, final results, deduplication, and deadlines.
- `PendingAudioReplay.kt` - bounded memory-only unfinished PCM suffix, final-offset pruning, partial-chunk trimming and safe replay availability.
- `BoundedAudioWriter.kt` - byte-bounded worker submission with capacity callbacks, FIFO backpressure, and JNI failure containment.
- `VoiceNetworkMonitor.kt` - validated-internet preflight and session-scoped Android network observation.
- `MaiSpeechSession.kt` - injectable SDK seam and `AzureMaiSpeechSession`, which owns native SDK objects and a process-wide serial worker for JNI calls/cleanup.
- `TranscriptSegment.kt` - completed text passed to the IME with punctuation attachment metadata.
- `TranscriptPostProcessor.kt` - local spoken punctuation, paragraph commands, and filler cleanup.
- `VoiceInputManager.kt` - microphone lifecycle, bounded audio/control and transcript FIFOs, silence/pause boundaries, verified local insertion, EOF draining, network failure stops, and rotation.
- `VoiceRecorder.kt` - mono PCM16 at 16 kHz with adaptive local silence detection.

## SDK and lifecycle contracts
- Follow [Microsoft's MAI Speech SDK guide](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/mai-transcribe-2-streaming-speech-sdk) and the pinned Java SDK API. Select the case-sensitive service identifier `mai-transcribe-2-streaming` explicitly. A live Central US check accepted this lowercase ID and rejected the title-cased display name used in Microsoft's examples; see `docs/mai-transcription.md`.
- Authenticate `SpeechConfig.fromEndpoint` with the resource key and `wss://<region>.stt.speech.microsoft.com/speech/universal/v2`. Regions are centralus, swedencentral, and southeastasia; key and region must match.
- SDK dictation supports Android API 26+ and ARM32/ARM64/x86-64. The app minimum remains API 21. Avoid creating native objects on unsupported devices.
- Start continuous recognition on the worker, then release buffered audio. Push headerless PCM16 in 100 ms chunks. Bound local audio to 300 chunks and queued worker audio to 256 KB. Backpressure retains the FIFO head and resumes on worker capacity; never confuse local acceptance with a service ACK. EOF/rotation wait for the local FIFO. An advisory commit records its captured-chunk sequence and runs after that boundary is accepted, before post-pause audio; never let a resumed phrase move the commit boundary. Captured boundaries form a FIFO bounded to 64 controls; overflow is terminal instead of dropping or coalescing requests. A delayed older boundary cannot start a final deadline for a newer speech epoch.
- Forward every captured PCM chunk through the FIFO; local VAD never discards quiet audio or waits for onset. Silence only triggers advisory commits and auto-stop.
- Local silence and pause request `PushAudioInputStream.commit()` only for new unfinalized audio. Requests are advisory; final offsets and echoed commit tokens can settle boundaries. NoMatch settles without insertion. Missing confirmation triggers graceful EOF drain/replacement, never an acknowledgment error or guessed completion.
- Only final RecognizedSpeech results reach the editor. Deduplicate result IDs, allowing equal text in separate results. Intermediate results never reach the editor; the SDK forwards only a text-free interim notification for liveness.
- Keep each final at the bounded 64-entry transcript FIFO head until the listener reports local dispatch/cleanup success. Rejection/exception cancels the session without a marker and prevents later writes. Reentrant callbacks must not duplicate the FIFO head. Android remote `InputConnection` success is not a host receipt; never retry a possibly partial edit.
- Startup failures before readiness leave the editor untouched and report the reason. Actual failures after capture/readiness preserve inserted finals and attempt one literal `[Dictation interrupted]`; marker insertion verifies the host caret and preserves selections, bypassing punctuation and paragraph cleanup.
- Interactive keyboard hiding, input/view finish, target changes, and verified nonempty-to-empty host transitions cancel all work immediately, including drain. Monitor extracted text and read the actual host even without selection changes. Null queries are unavailable, not empty. Screen-off hiding alone preserves capture; an explicit stop drains.
- Verify actual host selection positions/text before a paragraph or punctuation replacement. Temporarily close/reopen the host batch before readback for deferred editors; restore caches/caret best-effort after failure. Delayed cursor callbacks only preserve recording when the current host caret matches the expected voice caret.
- Shared punctuation normalization removes preceding period/comma runs before correction punctuation, plus a single period followed by horizontal whitespace and a Unicode lowercase letter. Preserve uppercase sentence starts, paragraph breaks, ellipses, common/dotted abbreviations and spoken-command terminators before conversion. Apply within incoming finals and paragraphs. `previousPunctuationReplacement` also prepares a verified replacement across finals, retaining preexisting spaces/tabs after the period, including before earlier paragraphs of a multiline final. Literal interruption markers bypass normalization. This casing heuristic can join an intentionally lowercase sentence start.
- MAI final diagnostics contain length, final/accepted byte counts, attempt and punctuation counts (`periods`, `lowercaseContinuations`) before local cleanup, allowing provider-origin combinations to be observed without transcript logging.
- Main-looper session tokens suppress stale SDK events. JNI operations and stop/disposal share one process-wide serial worker, ordering old disposal before replacement creation. Stop rechecks ownership after recorder shutdown and state callbacks before restoring processing UI or queuing EOF. Its 20-second absolute manager deadline includes startup/upload/replay/EOF; blocked recovery restarts report pending work instead of silently ignoring the tap.
- Stop closes push input and waits for EOF/session termination before disposal. Processing remains active through finalization. Mic restart during drain captures immediately and buffers until outgoing EOF, preserving final-text order. Pause retains the session for resume. Rotation at 55 minutes drains outgoing input while new chunks buffer.
- Microphone startup/read failures and local buffer overflow stop capture and report one error while preserving the outgoing session and accepted buffered audio through EOF. Ignore later recorder callbacks, block restart until drain, keep processing visible, then mark `[Dictation interrupted]`. Explicit cancel discards pending work; terminal connection/SDK failure marks only unconfirmed speech or undispatched text once; quiet/advisory tails alone do not cause a marker.
- Use a 30-second startup deadline, 60-second boundary fallback to drain, and a separate 20-second EOF deadline. The 64-boundary limit also requests drain. Do not treat a deadline as a recognition latency guarantee.
- Require validated internet before opening the mic. Network loss or input-open SDK disconnect stops capture and retains saved audio, allowing three seconds for SDK recovery. Local recognizer startup permits writes; log remote transport readiness separately. Transient cancellation, grace expiry and unexpected end allow at most two replacement attempts with 500/1500 ms backoff and a 20-second recovery budget. Authentication/configuration/quota, PCM/JNI and inconsistent timing errors are terminal. Never automatically restart capture.
- Bound the oldest local chunk awaiting upload to 30 seconds. Active speech/pending words have a 30-second response watchdog; live interims reset liveness. A separate 30-second missing-final wait starts at the current speech epoch's submitted boundary, only for pending recognized words. Repeated interims/controls cannot extend it; new speech clears it. Quiet PCM/noisy hypotheses alone do not require a final. Stop clears speech watchdogs and uses the separate 20-second EOF deadline. A progress timeout stops capture and blocks restart while preserving finals through EOF; equal-deadline silence auto-stop takes precedence. Missing advisory confirmation alone is not lost speech.
- The SDK owns ACKs; never parse undocumented ACK payloads. A successful push write is only local acceptance. Retain 30 seconds/960 KB of PCM in memory and prune only with final offsets/correlated final tokens. Replacement replays the complete retained suffix with sample-aligned cuts and absolute offset mapping; refuse replay if the suffix was evicted or visible text had no usable timing. Replay respects backpressure and precedes newer audio/EOF. Public finals do not prove every word was recognized. Ignore stale callbacks from disposed sessions.
- Never log raw SDK cancellation details, credentials, or transcripts. Diagnostics contain lifecycle, error codes, and text lengths.
- LatinIME clears typed-word state with finishInput(), commits finals through InputConnection, and performs local paragraph cleanup. Preserve model punctuation, including em dashes. No editor context is sent upstream. The streaming guide documents no punctuation-strength or clean-style configuration. The integration leaves OutputFormat and ProfanityOption unset; do not assume generic Azure options are supported.
- Settings live in `latin/settings/TranscriptionPreferences.kt` and `settings/screens/TranscriptionScreen.kt`. The fixed mic invokes this pipeline; ToolbarKey.VOICE invokes Android's system voice IME shortcut.
- Chunk silence uses milliseconds throughout preferences, UI, manager, and recorder: default 1000 ms, supported range 100–30000 ms. The default RMS silence threshold is 100. Auto-stop remains in seconds. Recorder defaults share `Defaults.kt`; subsecond values must not be rounded or clamped to one second.
- JVM tests inject `FakeMaiSpeechSession`; device-native libraries require Android validation. `tools/mai-streaming-smoke-test.py` checks the service through the Python SDK with environment credentials.
