# Voice data flow

1. The fixed right-edge microphone invokes LatinIME's VoiceInputManager.
2. TranscriptionPreferences supplies the Speech resource key, matching region, and language detection setting. Local preferences configure silence and auto-stop.
3. VoiceRecorder captures mono 16 kHz PCM16. VoiceInputManager queues startup audio while MaiTranscriptionClient starts the SDK session.
4. AzureMaiSpeechSession serializes SDK/JNI operations on a worker. The SDK manages the direct Azure connection and acknowledgements. Local worker backpressure retains the FIFO head until capacity is released.
5. The manager uploads chunks and requests advisory commits at silence and pause. A captured-chunk sequence and speech epoch keeps deferred commits before post-pause audio despite backpressure/resume. Every captured chunk enters the FIFO, including quiet audio; local VAD never discards audio and only requests commits/auto-stop.
6. The client handles final audio offsets/commit tokens, deduplicates result IDs, and suppresses stale callbacks. LatinIME clears typed-word state, inserts completed text through InputConnection, and runs paragraph cleanup with selected-range replacement in one commit. A failed replacement retains original text, attempts to restore the cursor, and cancels dictation. Local punctuation correction removes a single period before horizontal whitespace and a lowercase letter, preserving abbreviations, ellipses and paragraph breaks. Corrections spanning final results replace the previous period and any trailing spaces/tabs together while retaining whitespace, including before the first paragraph of a multiline final. The bounded transcript FIFO advances only after local dispatch/cleanup succeeds, and never retries partial edits. Verify actual host selection/text after flushing buffered host edits; remote booleans acknowledge dispatch only.
7. Stop, rotation, and unconfirmed-boundary fallback close push input and await EOF while finals continue arriving. A mic restart during drain captures into the buffer immediately; a replacement starts after EOF to keep transcripts ordered. Cancel invalidates tokens immediately and releases native resources asynchronously. Detected network/SDK failures cancel capture and recognition, mark uncertain speech, reject stale callbacks, and never automatically retry. Local capture failures preserve accepted speech to EOF while blocking restart, then insert a marker. Local upload and response waits are 30 seconds. Live interims refresh liveness without exposing text; missing-final waits start at the submitted speech boundary and cannot be extended by interims. Quiet PCM requires no final. EOF has a separate 60-second bound.

The manager owns recorder/UI state. The client owns lifecycle and pending boundaries. The SDK adapter owns native handles and worker calls. The IME owns editor mutation. Settings screens edit preferences. No editor context is sent upstream.

Startup rejection leaves editor text untouched. Actual failures after readiness/capture attempt one literal interruption marker without cleanup or replacement of highlighted text. Interactive keyboard hiding, target disconnection, and verified host clears invalidate all work immediately, including drain. Extracted-text monitoring plus actual host reads detect clears without cursor movement; unavailable reads do not imply emptiness. Explicit mic stop still drains, and screen-off hiding preserves recording.
